FRCContour Model Summary


v37.1 — Jul 2026 · M sandbox · Water Quality Division · 🌡 Temp-Corrected K (Arrhenius)



🌸 Real-time FRC Contour ทำงานยังไง



FRCContour ใช้หลัก EPANET Simplified — คำนวณคลอรีนคงเหลือ ณ ทุกพิกเซล ผ่านสูตร First-Order Decay ที่ได้จากงานวิจัย EPANET-MSX ผสานกับข้อมูล live จากภาคสนาม:

A. ค่า FRC จริงจาก sensor เป็นจุดเริ่มต้น (C₀)

B. ระยะทางจาก sensor ไปแต่ละพิกเซล คำนวณจาก pipe network จริง (Dijkstra)

C. ความเร็วน้ำ (velocity) จากข้อมูล live (DMA/RTU) → คำนวณเวลาเดินทาง (travel time)

D. ใช้สมการ First-Order Decay: C = C₀ · exp(−K · t) คำนวณ FRC ณ พิกเซลนั้น





Priority Chain (ต่อพิกเซล):



1. VC zone override (Valve Chamber active) →

2. CUSTOM_ZONES polygon (โซนสถานีสูบจ่าย กำหนดเอง) →

3. Pipe-network Dijkstra (หาสถานีต้นทาง+ระยะทางตามท่อจริง) →

4. Fallback geographic IDW (จุดที่ pipe grid ไม่ครอบคลุม)






🧪 ค่า K (Decay Rate) มาจากไหน



K แบ่งเป็น 2 องค์ประกอบตามหลัก EPANET-MSX:

K_total = Kb + Kw × (4/D) [1/day]


Kb (Bulk decay) — ปฏิกิริยาในน้ำเอง อ้างอิงงานวิจัย ม.เกษตร กนว.32/2566:

  • บางเขน (บข.) = 0.778/day (half-life 21 ชม.)

  • มหาสวัสดิ์ (มส.) = 0.400/day (half-life 42 ชม.)

Kw (Wall decay) — ปฏิกิริยากับผนังท่อ ค่า default = 0.05/day

D — เส้นผ่านศูนย์กลางท่อเฉลี่ย




🌡 Auto K ตามอุณหภูมิ — Arrhenius (v36)



อัตราการสลายคลอรีนไวต่ออุณหภูมิมาก (K เพิ่ม ~3 เท่า จาก 20→30°C) — ระบบจึงปรับ K อัตโนมัติตามอุณหภูมิน้ำจริง:



K(T) = K × exp(−(E/R) × (1/(T+273) − 1/(Tref+273)))



A. E/R = 8971 K — อ้างอิงงานวิจัย ม.เกษตร (Kongbuchakiat et al. 2025, Results in Engineering — โรงงานผลิตน้ำบางเขน)

B. Tref = 32°C — อุณหภูมิน้ำตอน calibrate K ภาคสนาม (เม.ย. 69) → หน้าร้อน factor ≈ ×1.0 และทำหน้าที่เป็นตัวปรับฤดูกาล

C. T ระบบ — median ของ tmp_6 (TWQMS) กรองเฉพาะช่วง 28–34°C ตัดสถานีที่วัดเพี้ยน (สำรวจจริง ก.ค.69, n=49)

D. ตัวอย่างผล: 32°C ×1.00 · 30°C ×0.82 · 28°C ×0.68 · 25°C ×0.50 — หน้าหนาว contour คงคลอรีนได้นานขึ้น (แก้ underestimate ช่วง ธ.ค.–ม.ค.)

E. Tref sync ผ่าน Firebase — ทุกเครื่องใช้ค่ากลางเดียวกัน ปรับด้วย setTempRef(°C) ใน console

เปิด/ปิดได้จาก sidebar → "🌡 Auto K ตามอุณหภูมิ (Arrhenius)" · ตรวจสอบ chain ด้วย _frcDiag(lat, lon)




💧 Live Data Sources



A. FRC Live (61 สถานี) — Firebase Realtime Database

  • SP01-12 (สถานีสูบจ่าย), SW01-11 (สถานีจ่ายน้ำ), SM01-06 (สถานี MDIS)

  • VC01-14 (Valve Chamber — ค่า sim จาก EPANET ไม่ใช่วัดจริง)


B. RTU Live (236 สถานี) — จาก SmartMap intranet

  • pressure ที่สถานี → คำนวณ velocity ผ่าน Bernoulli: v ∝ √(P/P_nominal)

  • match กับ 61 FRC sensor โดย nearest Euclidean → pFactor per-sensor




📊 Velocity Priority Chain



1. RTU Bernoulli (v ∝ √P) — pFactor clamp 0.5–2.0

2. Static pressure grid factor (fallback)

3. EPANET default velocity — ต่ำสุด




🎯 Zone Influence (การกระจาย contour)



A. Custom Polygon — วาดขอบเขต "โซนอิทธิพล" ของแต่ละสถานีสูบจ่ายด้วยมือ (Zone Editor)

B. Point-in-polygon — ทุกพิกเซลเช็คว่าอยู่ใน polygon ใด → assign สถานีต้นทาง

C. Pipe-aware distance — ถ้ามี pipe grid ครอบคลุม ใช้ระยะจริงตามท่อ (Dijkstra) แทน Euclidean

D. VC Simulation — Valve Chamber ที่ active (Valve% > 0) จะ override zone ของสถานีปกติ




🔧 Validate K (Field Calibration)



Calibrate ค่า K จากค่าคลอรีนจริงภาคสนาม เทียบกับค่า contour ที่ระบบคำนวณ:



Knew = Know − ln(I / AA) / tt



I=ค่าจริง, AA=ค่า contour, tt=travel time

วิธีใช้: AUTO-FIT K → "📋 Validate K (Field)" → paste แถวจาก Google Sheets
